# Cursor, Antigravity, T3 Code, OpenCode, and ZCode

Checked November 24, 2026. Prompt links were inspected or decoded without submitting a model turn. An HTTP response confirms a route is reachable, while app activation confirms the OS delivered a URI to a handler.

## Cursor

- Desktop prompt draft: `cursor://anysphere.cursor-deeplink/prompt?text=<encoded prompt>`. Cursor describes a prefilled chat requiring explicit review and confirmation. Its documented limit is 10,000 characters for the entire encoded URL. The `command` and `rule` routes have different effects, so a prompt button uses only `prompt`. [Cursor deeplink reference](https://cursor.com/docs/reference/deeplinks)
- HTTPS handoff: `https://cursor.com/link/prompt?text=<encoded prompt>`. An inert test containing spaces, literal `+` and `&`, and emoji received HTTP 200, with an `Open in Cursor` page title and the query present in its route state. This is the desktop handoff. `https://cursor.com/agents` also opens the cloud agents inbox on the web and is an iOS Universal Link to the same inbox. The iOS association lists launch, existing conversations, and pairing. It lists neither the desktop `/link/prompt` route nor a new prompt route. [Cursor cloud agents](https://cursor.com/agents), [Cursor for iOS](https://cursor.com/docs/cloud-agent/mobile), [iOS association](https://cursor.com/.well-known/apple-app-site-association)
- Android and web inbox: Cursor documents `https://cursor.com/agents` for the web client and for its installable Android web app in Chrome. A signed-out request reached the authentication redirect. Cursor does not document a prompt parameter for this inbox. [Cursor Cloud Agents access](https://cursor.com/docs/cloud-agent#how-to-access)
- macOS 3.31.15: checked the official arm64 DMG and Gatekeeper accepted the app as a Notarized Developer ID build. The app's plist declares `cursor`. The shipped `workbench.glass.main.js` dispatches authority `anysphere.cursor-deeplink` and path `/prompt` to `handlePrompt`, which calls `deeplink.prompt.prefill` with the decoded `text`. The mounted app accepted an application-directed `open -g -a` delivery. The isolated profile logged successful activation of the bundled extension for `onUri:anysphere.cursor-deeplink`. The Cursor Agents window opened to Log In / Sign Up in a fresh profile. Signed-in composer prefill remains unverified. [Cursor downloads](https://cursor.com/download)
- Icon: `icons/cursor.svg` is `General Logos/Cube/SVG/CUBE_2D_LIGHT.svg` from the official archive, the dark-colored cube for light backgrounds. [Cursor brand kit](https://cursor.com/brand), [official archive](https://ptht05hbb1ssoooe.public.blob.vercel-storage.com/assets/brand/cursor-brand-assets.zip)

## Google Antigravity

- Desktop launch: `antigravity://`. Local Antigravity 2.34.0 declares the scheme in its macOS `Info.plist`. `NSWorkspace` resolved it to `/Applications/Antigravity.app`. After `open -g 'antigravity://'`, the already-running Antigravity process became frontmost. No prompt parameter was supplied.
- Desktop handler evidence: `dist/main.js` in the installed `Contents/Resources/app.asar` routes the OS `open-url` event to `handleDeepLink`, which raises a local window and forwards the link to the renderer, with explicit handling for sign-in return. The ASAR renderer handoff and examined vendor docs did not establish a public composer-prefill route.
- Browser launch: `https://antigravity.google.com/remote` returned HTTP 200. The web product provides access to remote Google-hosted agents on eligible accounts and to connected remote-control workstations. For mobile, Google links the `https://antigravity.google.com/` Remote Control dashboard and documents adding its web app to the home screen. iPhone and Android browser requests returned HTTP 200, and the mobile manifest declares `/` as its start path and standalone display. Native mobile and web prompt prefill remain unverified. [Remote Agents](https://antigravity.google/docs/remote-agents), [Remote Control](https://antigravity.google/docs/remote-control/#connecting-from-a-web-browser), [Web manifest](https://antigravity.google.com/assets/manifest.json)
- Icon: `icons/antigravity.svg` is Google's full-color press SVG. [Google press assets](https://antigravity.google/press), [official SVG](https://antigravity.google/assets/image/brand/antigravity-icon__full-color.svg)

## T3 Code

- Desktop and native mobile prompt draft: `t3code://new?prompt=<encoded prompt>`. The stable v0.1.11 parser maps this to `/new`. Desktop accepts links into the renderer and the mobile new-task handler inserts `setComposerDraftText`. Mobile requires a connected environment. A prompt without a repository needs an environment configured for scratch tasks. [Stable release](https://github.com/pingdotgg/t3code/releases/tag/v0.1.11), [shared parser](https://github.com/pingdotgg/t3code/blob/v0.1.11/packages/shared/src/promptLinks.ts), [desktop handler](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/desktop/src/app/DesktopWebLinks.ts), [mobile scheme](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/mobile/app.config.ts), [mobile draft handler](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/mobile/src/features/prompt-links/newTaskPromptLink.ts)
- Hosted link: `https://app.t3.codes/new?prompt=<encoded prompt>`. An inert prompt URL returned HTTP 200. The deployed JavaScript includes the draft notification and browser/app opener selection. The browser client requires a connected T3 environment. Mobile HTTPS app association covers `/threads/` and the custom scheme handles new mobile drafts. [Hosted landing source](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/web/src/components/promptLinks/HostedPromptLinkLanding.tsx), [T3 Code remote access](https://github.com/pingdotgg/t3code/blob/v0.1.11/docs/user/remote-access.md)
- Self-hosted browser draft verified with v0.1.11 in fresh Chromium. An isolated loopback `t3 serve --mode web` backend issued a temporary grant. After authenticating, the browser opened `/` long enough to receive shell and server-configuration subscriptions, then opened `/new?prompt=…`. It navigated to `/draft/<UUID>` and the visible editor exactly matched `Agent Deeplinks T3 stable browser draft + & 🧪`. The prompt was left unsent. Direct cold loads had remained on **Still connecting** for 30 seconds on the stable server and for 22 seconds on the separate nightly test server. The successful check establishes local browser prefill with a connected environment. [T3 Code remote access](https://github.com/pingdotgg/t3code/blob/v0.1.11/docs/user/remote-access.md)
- `prompt` is limited to 8,000 JavaScript string code units before sanitization. The parser normalizes some line endings, drops hidden/invisible characters, and trims whitespace. Optional `repo` is a GitHub owner/name or HTTPS repo URL. Optional `provider` can be combined with `model`; the first-party builder emits `model` only with `provider`. `pr` and existing thread navigation are separate flows. [Parser](https://github.com/pingdotgg/t3code/blob/v0.1.11/packages/shared/src/promptLinks.ts), [parser tests](https://github.com/pingdotgg/t3code/blob/v0.1.11/packages/shared/src/promptLinks.test.ts)
- A local Node probe ran the released parser and passed native and hosted round-trip of an inert prompt with reserved characters, a newline and Unicode, plus rejection above 8,000 units. On macOS, the official arm64 v0.1.11 ZIP matched the release SHA-256 and passed Gatekeeper as Notarized Developer ID. A cold, application-directed `t3code://new?prompt=…` opened New thread with the exact inert draft `Agent Deeplinks probe + & 🧪` in the composer, with Send awaiting user action.
- Android draft prefill passed in the official signed 2.3.0 beta build 816 on an isolated Android 16 emulator. The APK matched its published SHA-256. The app paired through its native Add environment form with a matching nightly loopback server and showed Connected. A browsable `ACTION_VIEW` dispatch of `t3code://new?prompt=…` opened the link review. The editable New thread composer then showed the exact inert draft `Agent Deeplinks T3 official Android draft + & café 🧪`, with Send available. The scratch server recorded zero orchestration threads and zero provider turns. An earlier Android 15 test reached the no-environment warning and encountered repeated system ANRs during pairing. [Official beta release](https://github.com/pingdotgg/t3code/releases/tag/v0.1.12-nightly.20261123.5165)
- An iOS interop probe passed two library-generated URLs through the exact nightly mobile app-link filter and upstream new-thread parser at commit `67c442a17e6e5d6c9f768714820cecb5f15d4f9b`. Newlines, Unicode, punctuation, and optional repository, provider, and model values survived. The same checkout passed all 50 tests across app linking, prompt-link models, thread prompt links, and pairing. These checks cover the release source. The installed iOS composer remains unverified. [Nightly mobile filter tests](https://github.com/pingdotgg/t3code/blob/v0.1.12-nightly.20261123.5165/apps/mobile/src/lib/appLinking.test.ts)

## OpenCode

- Desktop prompt draft: `opencode://new-session?directory=<encoded absolute local path>&prompt=<encoded prompt>`. The v1.19.6 parser requires `directory` and routes through its legacy layout. The currently advertised desktop download is v2.4.1, which implements the same syntax in a shell-level receiver. Its source waits for the built-in server, adds the folder as a project and calls `tabs.newDraft` with the prompt. `opencode://open-project?directory=…` uses the same project opening flow without a prompt. Desktop Linux or Windows has not been exercised here. [v1.19.6 URL parser](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/app/src/pages/layout/deep-links.ts), [v2.4.1 parser](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/app/src/shell/deep-links/machine.ts), [v2.4.1 shell receiver](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/app/src/shell/deep-links/deep-links.ts), [official download](https://opencode.ai/product)
- Self-hosted web launch: supply the user's OpenCode server origin. The released source contains an internal project route `<origin>/<base64url-encoded UTF-8 absolute path>/session?prompt=<encoded prompt>` and a query consumer. Two fresh browser tests against isolated `opencode serve` v1.19.6 returned HTTP 200 and redirected to `/new-session?draftId=<UUID>` with an empty composer and the `prompt` query discarded. Treat the web client as launch-only. The same web UI works in phone browsers. [Web setup](https://opencode.ai/docs/cli/web/), [app routes](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/app/src/app.tsx#L620), [path encoder](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/core/src/util/encode.ts#L1)
- macOS v1.19.6 default layout: the official ARM64 ZIP matched the release SHA-256 and passed Gatekeeper. Its temporary profile logged application-directed cold and warm `new-session`, bare `opencode://`, and `open-project` receipt. After deferring the optional major upgrade, a loopback-only renderer check showed the default New session composer still empty after the draft delivery. The selected **Default Project** remained unchanged after `open-project`. This release retired the legacy interface on September 14, 2026 and forces the new layout after that date. A local Node probe separately verified the released legacy parser's Unicode round-trip and directory requirement. [v1.19.6 release](https://github.com/anomalyco/opencode/releases/tag/v1.19.6), [legacy layout sunset](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/app/src/context/settings.tsx#L60)
- macOS v2.4.1: the official ARM64 download passed Gatekeeper. An initial visible test prefilled the exact prompt and inherited an earlier test project through a stale loopback sidecar. After stopping that helper, a fresh read-only mount ran the unmodified app with `OPENCODE_TEST_ONBOARDING=1` and temporary XDG data, config, cache, and state roots. Its own child sidecar started under the new scratch profile. After one renderer reload, a warm `new-session` dispatch showed the exact `OpenCode QA isolated draft + & café ☃` in the editable Prompt with Send available, and the footer selected the canonical path of the requested committed scratch Git project. The draft was left unsent. [Official v2.4.1 DMG](https://opencode.ai/files/bin/2.4.1/opencode-desktop-mac-arm64.dmg), [desktop debugging options](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/desktop/src/main/diagnostics/options.ts)

## ZCode by Z.ai

- Desktop workspace launch: `zcode://workspace/open?path=<encoded absolute local directory>`. Gatekeeper accepted the official ZCode 4.0.0 Apple Silicon DMG as Notarized Developer ID. Its `Info.plist` declares `zcode`, and the shipped Electron entry point `out/main/index.js` contains both the Finder workflow URL builder and the OS handler. The handler reads `path`, requires an existing local absolute directory, rejects network paths, and requests confirmation before opening it. The extracted entry point matches its ASAR SHA-256. UI execution remains unverified. [ZCode downloads](https://zcode.z.ai/en), [official 4.0.0 DMG](https://cdn-zcode.z.ai/zcode/electron/releases/4.0.0/macos-arm64/ZCode-4.0.0-mac-arm64.dmg)
- With the signed 4.0.0 image mounted read-only, macOS LaunchServices accepted application-directed links to an empty temporary directory. The first startup passed a temporary Electron data-directory argument. The second dispatch started a fresh default profile, which was stopped and relocated into the scratch test directory. Native confirmation and workspace opening remain unverified.
- The stock v4.0.0 desktop URL dispatch handles workspace open, OAuth and payment callbacks, and share import. The workspace route only reads `path`, and the public docs checked do not specify any external new-task prompt URI. [ZCode FAQ](https://zcode.z.ai/en/docs/qa)
- Web/mobile Remote Control uses a URL or QR code issued by the user's online ZCode desktop app for use in a phone browser. It supports opening a draft from a connected interface. No universal Remote Control host or public prompt-prefill parameter was verified. The Z.ai chat product at `chat.z.ai` is a separate client. [Remote Control](https://zcode.z.ai/en/docs/remote-control)
- Icon: `icons/zcode.svg` is the vector within the first-party homepage navigation's `ZCode homepage` link. The page's CSS class was removed during export. [ZCode homepage](https://zcode.z.ai/en)
