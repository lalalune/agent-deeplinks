## Parameters and prerequisites

- **Codex desktop** accepts `prompt`, absolute local directory `path`, and `originUrl` to match a Git remote to an existing workspace. It tries the supplied path first and falls back to the Git remote if the path does not resolve to a directory. `codex://new` requires at least one supported parameter. The documented composer holds the prompt until the user sends it. [ChatGPT desktop commands](https://learn.chatgpt.com/docs/reference/commands#deep-links)
- **ChatGPT and Codex desktop registration**. OpenAI's Windows x64 and arm64 MSIX files (26.1120.5083.0) register `codex` for `ChatGPT.exe`. The Linux x64 preview DEB (26.1120.41243) declares `x-scheme-handler/codex` and launches `chatgpt %U`. [Windows deployment](https://learn.chatgpt.com/docs/enterprise/windows-deployment) · [Linux preview](https://learn.chatgpt.com/docs/linux/linux-app)
- **Linux native delivery**. On Ubuntu 24.04 x64, the official preview DEB matched OpenAI's signed APT metadata and SHA-256 `3baa1e745a5a3f59f917e92f25b9edf1284a0306b75f1f2e360a766df38b8b23`. Fresh GIO and XDG profiles automatically selected the installed `chatgpt.desktop` handler. GIO-backed `xdg-open` cold-launched the installed executable with each exact library-generated URL, including the full Unicode draft and `mode=chat` for ChatGPT. Both produced a native window titled ChatGPT. The test used no account, and the screenshots did not expose a composer. - **Installed desktop handler** in ChatGPT 26.1117.41037 has an Electron `open-url` listener that routes through the parser in `app.asar` member `.vite/build/early-bootstrap-7-ce4a67f0257ee973.js`. It recognizes `threads` with `/new` and the `new` host, and passes a valid mode and prompt to `newThread`. The corresponding handler in `early-bootstrap-916-90e0adb52d70fbc5.js` resolves the workspace and navigates with the mode, a composer focus request, and `prefillPrompt`. Both inspected members matched their declared SHA-256. REA reported an integrity mismatch in a separate unpacked native companion and returned partial JavaScript analysis at its deadline. The route evidence comes from the two packed members read directly. This establishes the shipped code path. Visible composer verification remains pending.
- **ChatGPT web** reads `q` or `m` on the root path. Its current client checks `params.has("disable_auto_send")` before auto-submission. This is shipped behavior and can change as the web client is updated. [ChatGPT web client asset](https://chatgpt.com/cdn/assets/646436.8f73ec6517.js)

- **Claude Code CLI** accepts `q` up to 5,000 characters, absolute local `cwd`, or a GitHub `repo` of the form `owner/name`. `cwd` takes precedence. - **VS Code extension source check**. The official macOS arm64 and Linux x64 Claude Code 2.1.331 packages carry the same `extension/extension.js` bytes (SHA-256 `9dead0c8f6970cb4120bd002ee1eb2b10d025677941e4fc19c7162c67f3f25fa`, CRC32 `4cd30a13`). The workspace trust and sign-in gates remain part of the normal app flow.
