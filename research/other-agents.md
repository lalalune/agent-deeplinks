## Grok and Grok Bot

Grok chat and Grok Bot are separate products. The November 19 [Grok Bot deeplink documentation](https://docs.x.ai/grok-bot/deep-links) supersedes the older glossary's assessment. The draft is filled only when the destination composer is empty. Without an ID the signed-in user needs a primary Bot. The published first-party builder replaces C0/C1 controls, including line breaks, with spaces, rejects empty messages, caps the message at 1,000 UTF-16 units, and caps the encoded native URL at 2,048 characters. The HTTPS form launches the installed app, with a separate confirmation or install flow depending on platform. [Published builder JavaScript](https://docs.x.ai/_next/static/chunks/2908rqvp8ew4d.js), [Observed HTTPS handoff](https://cursor.com/grok-bot/link/v1/prompt?text=Deeplink%20verification).

The Grok Bot prompt handoff also returned the documented native anchor to an Android browser. Cursor and xAI both publish Digital Asset Links for production Android package `ai.x.grok.bot` with the same signing fingerprint. xAI's iOS association claims separate plugin, Bot, and shared-template URLs. Installed mobile dispatch and draft handling remain unverified. [Mobile setup](https://docs.x.ai/grok-bot/mobile) · [Cursor Android association](https://cursor.com/.well-known/assetlinks.json) · [xAI Android association](https://x.ai/.well-known/assetlinks.json) · [xAI iOS association](https://x.ai/.well-known/apple-app-site-association)

The browser handoff test intercepted only the automatic URI navigation to record its destination. The visible button retained its real href. Both used the package's exact `grokbot://app/v1/prompt` URL and preserved Unicode, spaces, and the literal plus sign. No installed app or signed-in composer was exercised. [First-party handoff script](https://cursor.com/_next/static/immutable/chunks/2_3pegvaaij0f.js)

The [official macOS download](https://x.ai/bot) resolved to Grok Bot 1.2.3 for Apple Silicon. The 159,560,653-byte DMG mounted read-only. Its bundle ID is `com.anysphere.sand`, its notarized Developer ID is Anysphere Incorporated (team `DCNK4UB866`), and the app declares `grokbot` and `sand` URL schemes. Strict signature verification and Gatekeeper assessment passed. LaunchServices accepted the documented prompt URL, and the signed app opened a window from the mounted image with a temporary profile. Upstream docs require a signed-in Bot for composer acceptance. The launch check did not establish whether the marker reached the composer. No sign-in or prompt submission was performed.

Grok's iOS and Android 15 association files both include a catch-all and explicitly exclude links with `stay_in_browser=true`. The Android entry names the production package `ai.x.grok`. The blank browser link with the exclusion returned HTTP 200. The two mobile entries use the associated root without a query. In an isolated signed-out browser test of the original `q` link, the HTTP query appeared in the React Server Components payload and stayed in the address, while the visible composer remained empty. A retest with `q` and `stay_in_browser=true` returned HTTP 200. The browser removed the exclusion parameter from its address during page startup and the composer remained empty. Both browser runs blocked non-read HTTP requests and WebSockets. No intercepted request contained the marker. Signed-in behavior remains unverified. [Grok overview](https://docs.x.ai/grok/overview), [iOS association](https://grok.com/.well-known/apple-app-site-association), [Android association](https://grok.com/.well-known/assetlinks.json).
